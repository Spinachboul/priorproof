# Retention and deletion policy PP-RETENTION-v1

The demo supports a case-specific retention review date and a recorded legal hold. Review dates use UTC calendar dates for enforcement. A future date or active hold blocks application deletion of that case and its source documents. Removing an active hold requires explicit acknowledgement that the organization cleared it. A reached or unset review date provides no legal determination of whether deletion is permitted. Staff must assess the applicable retention obligations before confirming deletion. No automatic expiry, scheduled purging or statutory medical-record duration is imposed.

Confirmed application deletion removes case data, document records and extracted page text, fields, privacy authorization, privacy reviews, requests, and LangGraph state. Findings are computed from the deleted page text at request time. The existing queue unlinks application-managed originals, in-case artifacts and legacy cached packets and retries failures. The current packet, preview and summary routes produce responses in memory. Case-scoped activity is removed and a minimal case deletion event remains. Organization-wide security-event retention is an operational responsibility.

SQLite secure-delete is enabled for application connections. Application deletion does not cover external backups, exported or downloaded files, mobile temporary copies, database snapshots, WAL copies made elsewhere, storage recovery, or filesystem-level sanitization. Verify these separately before representing an erasure request as fulfilled.
