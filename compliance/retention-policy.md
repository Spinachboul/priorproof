# Draft retention and deletion policy

The current configuration retains case data locally until the demo owner explicitly deletes it. No automatic expiry or scheduled record purge runs. End the demo with an empty or disposable data directory if no retention is needed.

Deletion removes the case, uploads, page text, extracted values and their related activity rows. It queues original files and any legacy cached packet for unlinking. A minimal deletion event remains. Failed file operations remain in a retry queue and are retried on startup or repeat deletion. Packet bytes generated by the current route are held in memory and sent directly to the browser.

SQLite connections enable secure_delete. This does not guarantee secure erasure of database copies, backups, storage snapshots, filesystem blocks or exports. Backup retention and physical sanitization are deployment operator responsibilities.
